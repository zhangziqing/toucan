# Nanhu partition sweep on RTX 3090

All five frozen layouts passed full workload validation on November 19, 2026
UTC. The best tested layout was p40: median paired evaluation speedup
**1.502561x** over a freshly measured p20 baseline. Both NCU collections
passed all 13 application-replay endpoint gates. NSYS p40 produced valid
profile data but its action failed during process cleanup; that failure is
retained separately from the accepted correctness and timing results.

## Correctness and resources

Every layout passed loop1 and loop1000 before timing: complete commit and
device traces, 169 sampled watch records, all 32 final GPRs, trap, retirement,
cycle endpoints and device counters. Watch offsets were rebound by name.
Loop1 completed at cycle 8,511 with trap 8,507, 19 retired and 120 RAM reads;
loop1000 completed at cycle 10,645 with trap 10,641, 8,011 retired and 108 RAM
reads. Both had zero RAM writes and three flash reads.

PC/instruction columns are oracle values, not observed DUT values. The six
watches sample specified state; raw state pools are not compared across
layouts. These workload checks do not constitute general cycle equivalence.

Every actual resource probe selected `evalFreeRunningNCycles_Large`, with

shared bytes through the live API. Local bytes alone do not establish the
number of register spills. No value-pool spill was introduced. The device
reported 101,376 opt-in shared bytes/block and 102,400 shared bytes/SM.

but it used a different target architecture, toolkit/build and session; this
is not an isolated comparison of GPU architectures.

## Profiling

NSYS recorded one persistent kernel per layout. Its SQLite exports passed
integrity checks, and independently queried kernel durations match the raw
CSV tables. API synchronization time overlaps GPU execution and must not be
added to the kernel duration. Both collections warned that device-side CUDA
event completion tracing can add overhead and false dependencies.

| Diagnostic | p20 | p40 |
| --- | ---: | ---: |
| NSYS persistent kernel (s) | 12.320697 | 8.288467 |
| NSYS GPU memory operations (s) | 0.140389 | 0.121391 |
| NSYS CUDA API total (s) | 13.346063 | 8.785759 |
| NCU achieved occupancy (%) | 67.022263 | 66.984239 |
| NCU SM throughput (% peak) | 23.946422 | 23.546788 |
| NCU DRAM throughput (% peak) | 31.984092 | 35.178652 |
| NCU DRAM bandwidth (Gbyte/s) | 291.464656 | 320.576051 |
| NCU barrier stall ratio per issue active | 19.472699 | 18.549339 |
| NCU long-scoreboard stall ratio per issue active | 15.141017 | 15.723722 |

The final two rows are the exported `.ratio` metrics, not percentages.
The shorter measured kernel comes with unchanged cooperative grid/residency
and nearly unchanged achieved occupancy. These observations do not isolate
the cause of the gain, and the throughput counters do not show saturation.

NCU used application replay, strict application matching, one matched
`evalFreeRunningNCycles_Large` launch and the LaunchStats, Occupancy,
SpeedOfLight, MemoryWorkloadAnalysis and WarpStateStats sections. Every one
of its 13 passes per layout started a fresh fully initialized application,
saved its own endpoint and passed independent offline validation. The raw
exports contain 565 columns each. Clocks were left unchanged; NCU warned
about uncontrolled clocks and slow workload launch. Those warnings remain
in the raw logs. NCU durations are diagnostics rather than benchmark samples.

NSYS p20 passed cleanly. NSYS p40's original action remains **failed** with
`Owned descendants remain: [4111056]`. Its native report was already created;
CPU-only endpoint validation, report export and SQLite/CSV checks passed.
The flagged process later appeared as a zombie and was absent in the final
follow-up. No GPU rerun was used to replace the failure, and it is not counted
as a cleanly passed NSYS action.
